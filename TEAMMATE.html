Goose quickstart

Goose is a voice personal assistant. It answers Pranav's phone number, knows who is calling, keeps private things private, and briefs him afterwards from a web app. This page gets you running so you can look around. No task yet: Pranav will share the split.

1. Clone and install (2 min)

You need Git and uv.

git clone https://github.com/PranavMishra17/talk-to-me---GOOSE.git
cd talk-to-me---GOOSE
uv sync --extra nc
uv run pytest -q

The tests need no keys and spend nothing.

2. See the web app, no keys needed

Mac or Linux:

GOOSE_MOCK=1 uv run uvicorn app.api:app --port 8000

Windows PowerShell:

$env:GOOSE_MOCK=1; uv run uvicorn app.api:app --port 8000

Open http://localhost:8000.

3. Talk to Goose in the terminal

Make a free account at cloud.livekit.io and create a project. Your own account has its own credits. Create a file named .env in the repo root with your own keys. It is gitignored.

LIVEKIT_URL=wss://YOUR-PROJECT.livekit.cloud
LIVEKIT_API_KEY=
LIVEKIT_API_SECRET=
OPENROUTER_API_KEY=

OPENROUTER_API_KEY is optional. Then run this, pick who is calling, and type:

uv run python scripts/call.py

Or skip the questions, and add --voice to use the microphone:

uv run python scripts/call.py --as owner
uv run python scripts/call.py --as muhammad
uv run python scripts/call.py --as unknown --pack jesse

Press Ctrl+C to hang up, because a running session spends credits. The call is saved.

Do not run app.worker dev on Pranav's LiveKit project: calls go to whichever worker LiveKit picks.

4. Starter prompt for your coding agent

Open Claude Code in the repo and paste this:

This is Goose, a voice personal assistant on LiveKit Agents in Python, built with uv. Read README.md, then give me a 10-line tour: how a phone call flows through app/worker.py and app/agent.py, what lives in proxy_core/, what the web app in app/api.py and web/ does, and how tests and scripts/harness.py prove behaviour. Then list the three things most worth trying by hand. Do not change, commit or push anything yet. Never read or print .env. Other work is landing on main often, so run git pull before you look.

Working rules

  • Pull often: git pull. Several people and agents are pushing to main.
  • The repo is public: no keys and no real phone numbers.
  • The phone call is what gets judged, so anything that makes it less reliable does not ship.
