What we learned building a fast LiveKit voice agent

From the Goose project, 6 to 11 November 2026: one LiveKit Agents worker answering real phone calls and web rooms. Written as a handoff for other teams to take what they want. Source: talk-to-me---GOOSE at aed43a1.

The short version. On LiveKit Inference with livekit-agents 1.8.11, our fastest reliable pipeline was Deepgram Nova-3 STT, the LiveKit audio turn detector, Gemma 4 31B, and Cartesia Sonic 3.5, with preemptive generation on but its retries capped at one. That gave about 0.9 to 1.8 s from the end of the caller's speech to the first agent audio. The biggest wins were not model swaps alone. They came from measuring every module separately, starting side work on the STT final in parallel with the LLM, pulling context before the call instead of using tools, and having code, not the model, speak the short lines that would otherwise be silence.

How strong is the evidence? Most numbers come from a scripted caller with a synthetic voice, in real LiveKit rooms, usually one run of a few turns per change, on a Windows laptop against LiveKit Cloud US East. Treat them as directional, not as benchmarks. Synthetic speech is known to fool audio end-of-turn models, so the endpointing numbers in particular need checking by ear on a real phone. Model A/Bs used scripts/model_ab.py with 5 to 24 turns per side.

3. The changes that mattered most

Measure every module, every run

We log every metrics_collected event as one JSON line, then group them per caller turn by speech_id, not by arrival order. Preemptive generation runs before the turn commits, so arrival order puts its LLM call in the previous turn's row. That was a real bug in our first table.

  • app/worker.py#L158: the metrics hook
  • proxy_core/latency.py: one row per turn
  • scripts/harness.py: a scripted caller in a real room, measuring first audio at the listener

Shortening endpointing alone made things slower

Cutting max_delay from 2.0 to 1.2 s made first audio worse, from 3.8 s to 5.2 to 5.9 s, on the slow LLM of the time. Preemptive generation had been hiding the LLM's latency inside the endpointing wait. Shorten the wait and the LLM's own time shows through. Fix the LLM first. We settled on min_delay 0.3, max_delay 1.5.

Cap preemptive generation's retries

With default retries, preemptive generation spent 3 to 4 LLM calls per turn as the transcript changed, which burned credit and widened the slow tail. We set max_retries: 1 and kept preemptive_tts: false.

Run side decisions in parallel with the LLM, with a hard cap

We use a small classifier, Jev on OpenRouter's decisions endpoint, for addressee, tone and injection. Two findings:

  • Reuse the HTTP connection. One shared httpx.Client took the median from 951 ms to 81 ms. Nearly all of that was TLS setup per call. proxy_core/decider.py#L8
  • Start it on the STT final, not in the turn hook. It then runs during the endpointing wait, beside the preemptive LLM call. The hook waits at most 300 ms for it, then falls back to keyword rules. In live calls the hook added 0 to 120 ms. app/agent.py#L210 and #L215

Pull context before the call instead of using tools

A tool turn costs about 1.3 to 2 s. For a known caller we build a short, permission-filtered bundle before the greeting: recent emails and messages with them, open tasks, past calls and free/busy time. It stays around 150 words, which kept LLM first token at about 250 ms. The first answer then needs no tool. Tools remain for going deeper. proxy_core/vault.py#L201, #L218

4. Make code speak where silence would happen

Fast models were unreliable at this, every time we tested it. Gemini flash-lite models called tools with no words first on most tool turns, ignored a prompt telling them to call a tool, and even ignored a forced tool_choice. One model hung up without a goodbye, and another kept talking after hanging up. So we put these in code, in llm_node: app/agent.py#L295

  • A filler line when the model starts a lookup with no words, such as "One sec", flushed with FlushSentinel so TTS starts at once. Instant actions get no filler: "Let me pull that up" before simply saving a message sounds wrong.
  • The goodbye before hanging up, spoken by code. end_call must return None: any tool output made the model speak again after the hang-up.
  • Confirmation questions before actions, as one short line. Never read tool arguments back. Callers called that robotic.

Also normalise text before TTS. Dates, times and phone numbers read as digits sound wrong on a call. We rewrite them in tts_node, holding text only until the next clause break. proxy_core/speech.py#L143

6. Traps that cost us time

Testing
  • Text turns skip on_user_turn_completed. That covers session.run(user_input=...), lk agent debugger and lk agent simulate text. Anything in that hook (gates, injection checks, hang-up logic) is only proved in a real room. Our text bench passed injection tests that the hook never ran.
  • Synthetic speech fools the audio end-of-turn model. Trust a harness for LLM, TTS and hook numbers, not for endpointing or turn-taking. Check those by ear on a real phone.
  • Real-room tests from several developers collide when workers share an agent name on one LiveKit project: a dispatch lands on any of them. We give every test worker a private agent name suffix. Only one untagged worker per project should serve the phone.
  • Test what passed offline in a real room. Our hang-up logic passed every unit test and never fired in a live call, because it counted the model's refusal wording.
Running on LiveKit
  • Use dev, not self-hosted start. According to the LiveKit docs, self-hosted start quietly drops adaptive interruption to VAD-only and uses a smaller turn detector.
  • The Inference credit cap covers STT, LLM and TTS together. When it ran out, every call failed with 429 MaxGatewayCredits, and switching LLM did not help. Keep a one-line switch to your own provider keys. We kept OpenRouter and Cartesia ready and proved them in a real room, at 0.84 to 2.04 s first audio. Separately, Gemma on Inference has a 100 requests per minute limit, and our test sessions hit 94 of it.
  • Attaching a dispatch rule to a number from the CLI failed with invalid_argument on two projects. Assigning it in the dashboard worked.
  • Prime the audio resampler on Windows. Twelve resamplers racing at first use crashed or hung 3 of 105 cold processes with a native soxr assertion dialog. After warming one resampler alone at import: 0 of 80 in the run recorded in the code, and 0 of 380 in a longer run one session reported. The dialog also blocks the process, so we exit it with a code a supervisor restarts. app/native.py
  • A native crash takes down the whole worker and every call in it, so run it under a restart loop. scripts/stage.py
Web callers
  • Loud rooms break open-mic web calls, even with earphones. We added hold-to-talk, where the browser tells the worker over RPC to commit the turn on release (app/worker.py#L92), and a typing mode as a fallback. Typed turns must run the same hooks as spoken ones.
  • Chrome can block agent audio when the call starts without a click on that page. Handle AudioPlaybackStatusChanged and offer a button that calls room.startAudio().
  • Echo: a speakerphone feeds the agent's voice back as caller speech. We drop a caller segment that heavily overlaps the agent's last 3 s of speech, with a 4-word minimum so short replies pass. proxy_core/echo.py#L12

7. What we did not test

  • Flux turn detection against the audio turn detector, by ear
  • Realtime or speech-to-speech models
  • Large samples: none of these numbers has more than a few dozen turns behind it
  • Endpointing on real phone audio at scale
